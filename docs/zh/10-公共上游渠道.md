# 10 — 公共上游渠道

> 代理默认聚合的一组固定、免认证的上游渠道：OpenCode Zen、免 key 的
> Pollinations（chat 与图片生成）、Felo 逆向网页协议。本文档记录每个渠道的
> 协议、实测行为、流式规范化层，以及客户端兼容性（如 Cherry Studio 的
> `AI_FinishReasonError`）。实现见 `src/public-upstream.ts`。

## 为什么需要公共渠道

代理有认证的 Freebuff 链路，也默认启用一组固定的公共能力。当请求的模型命中
公共白名单时，代理把翻译后的请求体发给对应的固定 HTTPS 提供商，**完全不转发
下游凭证**（不带 `Authorization`、`x-api-key`、Cookie 或 Freebuff token）。
公共路由优先尝试；瞬态失败时依次尝试其他匹配的公共渠道，最后才回退到认证的
Freebuff。也就是说，**零配置、没有 Freebuff token 也能提供服务模型**。

用 `PUBLIC_UPSTREAM_ENABLED=false` 关闭全部公共链路；用
`PUBLIC_UPSTREAM_PROVIDERS`、`PUBLIC_UPSTREAM_MODELS`、
`PUBLIC_UPSTREAM_IMAGE_MODELS` 缩小范围。

## 渠道清单

| 渠道 | Base URL（固定） | 认证 | 协议 | 实测模型 |
| ---- | ---- | ---- | ---- | ---- |
| OpenCode Zen | `https://opencode.ai/zen/v1`（可用 `PUBLIC_UPSTREAM_BASE_URL` 覆盖，仅限 HTTPS 的 `opencode.ai` 主机） | 无 | OpenAI chat、SSE 流式 | 4 个 chat |
| Pollinations chat | `https://gen.pollinations.ai/v1` | 无 | OpenAI chat、SSE 流式 | 8 个 chat |
| Pollinations 图片 | `https://image.pollinations.ai` | 无（去水印 `nologo` 需要 token，从不发送） | `GET /prompt/<prompt>?…`；带 `image` 参考图时 `POST` JSON 做 img2img → OpenAI images 响应 | 3 个图片 |
| Felo | `https://felo.ai` | 无 | 逆向网页协议（chat 类目），SSE 转成 OpenAI 流 | 5 个 chat |

模型 ID：每个模型只有一个带供应商前缀的 `provider/model` ID
（`opencode/big-pickle`、`pollinations/openai`、`felo/felo-chat`）。不带前缀的
裸 ID 不会被 `GET /v1/models` 列出，也不可路由。请求瞬态失败时按
`PUBLIC_UPSTREAM_PROVIDERS` 优先级回退到其余匹配 provider（`opencode` →
`pollinations` → `felo`，Freebuff 最后）。完整目录见
[09-模型目录](09-模型目录.md)。

## 各渠道行为

### OpenCode Zen（免认证）— 4 个

`opencode/big-pickle`、`opencode/deepseek-v4-flash-free`、
`opencode/mimo-v2.5-free`、`opencode/nemotron-3-ultra-free`

- 原生 OpenAI 兼容 `/v1/chat/completions`；ID 以 `opencode/<model>` 命名空间
  呈现。
- `hy3-free`、`north-mini-code-free` 已**移除**：实测无账号 token 时返回 401。
- **免费层是随机行为**（2026-08-08 实测）：一次请求可能完整输出
  `reasoning_content` 后以**空**正式回复结束
  （`{"delta":{"content":""},"finish_reason":"stop"}`）——模型想了但没回答。
  完全相同的 prompt 反复请求又可能返回真实回答，因此这是供应商侧抽签，不是
  代理的 bug。
- 偶尔流在**没有任何 finish chunk** 的情况下结束，或附带
  `{"choices":[],"cost":"0"}` 这类垃圾尾随 chunk（没有 `choices`/`usage`）。

### Pollinations chat（免认证）— 8 个

`pollinations/openai`、`pollinations/openai-fast`、`pollinations/openai-large`、
`pollinations/qwen-coder`、`pollinations/mistral`、`pollinations/deepseek`、
`pollinations/grok`、`pollinations/perplexity-fast`

- 这些模型匿名调用可用；`gemini-flash-lite-3.1`、`perplexity-reasoning`
  已**移除**（即使最简 prompt 也 401）。
- **与 prompt 相关的 401 抽签**（实测确认）：匿名网关有时会把某些 prompt
  形态路由到需认证的后端，返回 `401 "Authentication required"`——例如
  `"hi"` 稳定 200，而某次会话里 `"Reply with exactly: PUBLIC_MODEL_OK"`
  连续 10/10 都是 401。拒绝是按 (模型, prompt) 间歇发生的；代理把 401 视为
  瞬态，客户端重试即可（或依赖 Freebuff 回退）。
- **匿名层不支持工具调用**（2026-08-08 实测）：请求体只要带 `tools` 字段就
  **确定性** 401——`pollinations/qwen-coder`、`pollinations/openai`、
  `pollinations/perplexity-fast`、`pollinations/deepseek`
  全部 3/3 401，而不带 `tools` 时同一批模型 3/3 全 200。工具调用需要账号，
  因此带工具驱动的 Agent（opencode、Claude Code、Cline 等）无法匿名使用
  Pollinations chat——只有不带工具的普通对话可用。
- 突发时会限流；保持间隔的串行探测则一直健康。

### Pollinations 图片（免认证）— 3 个

`pollinations/flux`、`pollinations/turbo`、`pollinations/zimage`

- `GET https://image.pollinations.ai/prompt/<prompt>?width=…&height=…&seed=…&model=…&format=jpeg`，
  翻译为 OpenAI images 响应（`url` data-URI + `b64_json`）。
- **img2img / 图片编辑**：可选的 `image` 字段（data URI 或公网 URL，或最多 4
  个的数组）会把请求切换为 `POST`，参考图放进 JSON 请求体（已对线上上游实测
  验证；GET 查询串无法承载大体积 data URI）。
- `nologo`（去水印）需要账号 token，**从不**发送——匿名结果带 Pollinations
  水印。
- 图片同步拉取并 base64 编码后才响应，延迟随生成时长增长。没有认证兜底：
  瞬态失败直接返回给客户端（由客户端重试）。

### Felo（免认证，逆向网页协议）— 5 个

`felo/felo-chat`、`felo/felo-search`、`felo/felo-scholar`、`felo/felo-social`、
`felo/felo-document`

- 没有官方 API；适配器调用浏览器侧协议（`/api/message/v1/stream/<key>` 等）
  并转成 OpenAI SSE 流。
- 协议**可能随时变化**，直到适配器更新前该渠道会失效。
- 对话/搜索类目模型：单轮问答正常（已用 opencode 实测），但**没有工具调用
  能力**，无法驱动需要写文件、执行命令的编码 Agent。

## 流式规范化（`sanitizeOpenAIStream`）

所有公共 chat 流（OpenCode + Pollinations；Felo 适配器输出同样处理）在转发前
统一规范化，保证**严格解析器始终拿到格式良好的流**：

- **保证**终结 chunk `finish_reason: "stop"`：
  - 非标准 reason（如 `"other"`）改写为 `"stop"`；
  - 上游未发 finish chunk 就结束（OpenCode 免费层在 `reasoning_content`
    之后截断）时，补发终结 chunk；
  - Felo 协议本身不带 OpenAI finish chunk，适配器总是补发一个。
- `content` / `reasoning_content` 增量与 usage chunk 原样保留。
- 丢弃畸形行与垃圾尾随 chunk（如 `{"choices":[],"cost":"0"}`）。
- 流总是以唯一的 `data: [DONE]` 结束。

## 客户端兼容性与排查

**症状（Cherry Studio）：** 模型输出完 thinking/推理块后没有正式回复，并报：

```
AI_FinishReasonError: Response ended with finish reason "other"
```

**根因：** Cherry Studio 的提供商层基于 Vercel AI SDK，当 OpenAI 兼容的 SSE
流以未知或缺失的 finish reason 结束时，它会中止——把未知值映射为 `"other"`
并抛错。之前代理原样透传公共上游的流，因此上游发什么（缺失 finish chunk、
`"other"`、或在 `reasoning_content` 后截断）都会以该错误形式暴露。这是
**格式**问题，不是内容问题。

**修复：** 上述流式规范化作用于每条公共 chat 流，客户端总能收到干净的
`finish_reason: "stop"` + `[DONE]`——无论上游发什么，都不会再触发
`AI_FinishReasonError`。

**仍可能看到的现象：** 对 `opencode/deepseek-v4-flash-free`（免费层），上游偶尔会在
推理块之后以**空**正式回复结束。代理无法凭空生成内容；有了修复，请求会干净
结束而不是报错。回复为空时重试一次，或换用其他模型（`opencode/big-pickle`、
`opencode/mimo-v2.5-free`、某个 `pollinations/*` 模型、`felo/*`）。Pollinations 在突发
期间的 401 是瞬态的，重试通常能成功。

**其他 OpenAI 客户端**（curl、Claude Code、LobeChat 等）不受影响：它们本就
容忍宽松的流；规范化对它们无害。

## 配置项

| 环境变量 | 默认值 | 作用 |
| ---- | ---- | ---- |
| `PUBLIC_UPSTREAM_ENABLED` | `true` | 关闭全部公共渠道 |
| `PUBLIC_UPSTREAM_PROVIDERS` | `opencode,pollinations,felo` | 启用的渠道与别名优先级顺序 |
| `PUBLIC_UPSTREAM_MODELS` | 聚合白名单 | 公共 chat 模型白名单（`provider/model` ID） |
| `PUBLIC_UPSTREAM_IMAGE_MODELS` | `pollinations/flux,pollinations/turbo,pollinations/zimage` | 图片模型白名单 |
| `PUBLIC_UPSTREAM_BASE_URL` | `https://opencode.ai/zen/v1` | 仅覆盖 OpenCode（HTTPS 的 `opencode.ai` 主机） |
| `PUBLIC_UPSTREAM_TIMEOUT` | `20s` | 首响应超时，之后回退 |

公共渠道开启时，独立 CLI **完全不需要** `AUTH_TOKENS` 即可服务白名单公共模型。

## 隐私与服务条款

任何路由到公共渠道的请求都会把你的 prompt 与对话中的代码发送到对应提供商的
服务器（OpenCode / Pollinations / Felo），离开本服务。部署前请确认各提供商的
服务条款与隐私政策；如有顾虑，用 `PUBLIC_UPSTREAM_PROVIDERS` 关闭个别渠道，
或用 `PUBLIC_UPSTREAM_ENABLED=false` 全部关闭。Felo 是非官方的逆向集成，
随时可能失效。

## 验证

- 实时 E2E（`LIVE_PUBLIC_UPSTREAM_TEST=1`，需显式开启）经代理验证了全部默认
  公共模型：OpenCode chat（4）、Pollinations chat（8）、Felo（5）走
  `/v1/chat/completions`，Pollinations 图片（3）走 `/v1/images/generations`；
  前缀路由与 `/v1/models` 也覆盖。
- 实时流式检查：`/v1/chat/completions` 请求 `opencode/deepseek-v4-flash-free`
  以 `finish_reason: ["stop"]` 与末尾 `[DONE]` 结束。
- 单元测试覆盖：截断、非标准 finish reason、垃圾尾随 chunk、usage 保留、
  畸形行、JSON 透传、客户端中断、Felo 终结 chunk。
