# 07 配置与使用

> 本文汇总 freebuff2api 的配置项、常用命令与使用示例。
> 实现见 `src/config.ts`。

## 快速开始

```bash
bun install

# 方式 A（推荐）：设备码登录，凭证存 ~/.config/freebuff2api/credentials.json
bun run login

# 方式 B：直接提供 token
# export AUTH_TOKENS="<你的 freebuff.com token>"

bun run dev        # 或 bun run src/index.ts
```

```bash
curl http://localhost:23333/v1/models
curl http://localhost:23333/v1/chat/completions \
  -H 'Content-Type: application/json' \
  -d '{"model":"deepseek/deepseek-v4-flash","messages":[{"role":"user","content":"Hello!"}]}'
```

任何 OpenAI 兼容客户端指向 `http://localhost:23333/v1` 即可。

## 配置优先级

```
通用配置：环境变量 > config.json（当前目录或 ~/.freebuff2api/）> 登录凭证 > 默认值；HTTP_PROXY：命令行 `--http-proxy` > config.json > 环境变量
```

## 环境变量

| 变量 | 默认值 | 说明 |
| ---- | ------ | ---- |
| `AUTH_TOKENS` | 登录凭证 | 逗号分隔的 Freebuff token；多 token 轮换 + 401 冷却 |
| `UPSTREAM_BASE_URL` | `https://www.codebuff.com` | 上游后端地址 |
| `LOGIN_BASE_URL` | `https://freebuff.com` | 登录流程 base URL |
| `LISTEN_ADDR` | `:23333` | 监听地址（受托管环境 `PORT` 影响） |
| `REQUEST_TIMEOUT` | `15m` | 上游请求超时（Go 风格时长） |
| `ROTATION_INTERVAL` | `6h` | run 轮换间隔 |
| `API_KEYS` | 空 = 开放 | 客户端访问本代理所需的 key（可选） |
| `SITE_ACCESS_TOKEN` | 空 = 不启用 | 托管 Web 控制台门禁 token（逗号分隔）。设置后访客必须提供其中一个（锁屏输入，或 `?token=…`）才能解锁站点 |
| `HTTP_PROXY` | 空 | 上游 HTTP(S) 代理；优先级为 `--http-proxy` > config.json > 环境变量 |
| `MAX_BODY_SIZE` | `16MB` | chat 请求体上限（16,000,000 字节） |
| `MAX_CONCURRENT_REQUESTS` | `32` | 最大并发 chat 数 |
| `USER_AGENT` | 见下 | 覆盖 chat 请求的 User-Agent |
| `DEBUG_UPSTREAM` | 关 | `1` 时打印上游请求详情（token 脱敏） |

> `SITE_ACCESS_TOKEN`（仅 Web 应用）是托管控制台的**前门**：设置后，
> `POST /api/gate/verify` 负责校验访客提交的 token（SHA-256 恒定时间
> 比较）。访客要么在锁屏界面输入 token，要么用 `?token=…` 打开站点；
> 验证通过后浏览器保存在 `localStorage`，每次访问重新校验。它不影响
> `/v1` 接口——该接口始终由 `API_KEYS` 保护。

`USER_AGENT` 默认值（与官方 SDK 一致，实测任意版本均通过网关）：

```
ai-sdk/openai-compatible/0.10.7/codebuff ai-sdk/provider-utils/3.0.25 runtime/browser
```

## 常用命令

| 命令 | 说明 |
| ---- | ---- |
| `freebuff2api` / `bun run src/index.ts` | 启动代理 |
| `freebuff2api login` | 设备码登录 |
| `freebuff2api login --resume` | 恢复被中断的登录 |
| `freebuff2api login --force` | 重新登录（换账号/刷新 token） |
| `freebuff2api --help` | 帮助 |
| `freebuff2api --port 23333` | 覆盖监听端口 |
| `freebuff2api --listen-addr 127.0.0.1:9000` | 覆盖监听地址 |
| `freebuff2api --http-proxy http://127.0.0.1:7890` | 覆盖上游代理 |
| `node tools/model-availability.mjs` | 探测 `/v1/models` 返回的每个模型（会消耗额度） |
| `bun run typecheck` | 类型检查 |
| `bun run build:cli` | 打包到 `dist/index.js`（node 目标） |
| `DEBUG_UPSTREAM=1 bun run src/index.ts` | 带上游调试日志启动 |

## 代理内部端点

| 方法 | 路径 | 说明 |
| ---- | ---- | ---- |
| GET | `/healthz` | 存活 + 模型注册表 + 各 token 会话状态 |
| GET | `/v1/models` | 可用模型列表（OpenAI 格式） |
| POST | `/v1/chat/completions` | chat（流式/非流式） |

## 部署相关

- 打包产物：`bun run build:cli` → `dist/index.js`（`package.json` 的
  `bin.freebuff2api` 指向它）
- 生产环境（托管）：托管检测到 Next.js 应用后用 `bun run build`
  （即 `next build`）构建；CLI 产物用 `bun run build:cli` 单独打包。
  运行时不依赖外部服务
- 生产环境变量与沙箱 `.env` 分开管理，用 `freebuff-deploy env` 系列命令设置

## 安全提示

- token 等于账号的 API 使用权，请保密，不要提交到仓库
- 不要在 `.env` 中明文存 token 并提交；优先使用托管环境变量或登录凭证
- 免费档有速率限制（实测 deepseek-v4-flash 每日约 6 次基础额度，
  按太平洋时区重置），使用需节制
