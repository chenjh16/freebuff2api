# 07 配置与使用

> 本文汇总 freebuff2api 的配置项、常用命令与使用示例。
> 实现见 `src/config.ts`。

## 快速开始

```bash
bun install

# 方式 A（推荐）：设备码登录，凭证存 ~/.config/freebuff2api/credentials.json
bun run login

# 方式 B：直接提供 token
# export AUTH_TOKENS="<你的 freebuff.com token>"

bun run dev:cli    # 独立代理；`bun run dev` 是托管 Next.js 应用
```

```bash
curl http://localhost:23333/v1/models
curl http://localhost:23333/v1/chat/completions \
  -H 'Content-Type: application/json' \
  -d '{"model":"freebuff/deepseek/deepseek-v4-flash","messages":[{"role":"user","content":"Hello!"}]}'

# 图片生成（Pollinations 免认证）
curl http://localhost:23333/v1/images/generations \
  -H 'Content-Type: application/json' \
  -d '{"model":"pollinations/flux","prompt":"a tiny red circle on a white background","size":"256x256","n":1}'
```

任何 OpenAI 兼容客户端指向 `http://localhost:23333/v1` 即可。

## 配置优先级

```
通用配置：环境变量 > config.json（当前目录或 ~/.freebuff2api/）> 登录凭证 > 默认值；HTTP_PROXY：命令行 `--http-proxy` > config.json > 环境变量
```

## 环境变量

| 变量 | 默认值 | 说明 |
| ---- | ------ | ---- |
| `AUTH_TOKENS` | 登录保存的凭证 | 逗号分隔的 Freebuff token；默认公共白名单模型可不设置，Freebuff 专属模型、认证回退或关闭公共上游时需要 |
| `UPSTREAM_BASE_URL` | `https://www.codebuff.com` | 上游后端地址 |
| `LOGIN_BASE_URL` | `https://freebuff.com` | 登录流程 base URL |
| `LISTEN_ADDR` | `:23333` | 监听地址（受托管环境 `PORT` 影响） |
| `REQUEST_TIMEOUT` | `15m` | 上游请求超时（Go 风格时长） |
| `ROTATION_INTERVAL` | `6h` | run 轮换间隔 |
| `API_KEYS` | 独立模式空 = 开放；托管模式空 = fail closed | 客户端访问本代理所需的显式 key；托管部署应配置高熵值 |
| `SITE_ACCESS_TOKEN` | 空 = 不启用 | 托管 Web 控制台门禁 token（逗号分隔）。设置后访客必须提供其中一个（锁屏输入，或 `?token=…`）才能解锁站点 |
| `HTTP_PROXY` | 空 | 上游 HTTP(S) 代理；优先级为 `--http-proxy` > config.json > 环境变量 |
| `MAX_BODY_SIZE` | `16MB` | chat 请求体上限（16,000,000 字节） |
| `MAX_CONCURRENT_REQUESTS` | `32` | 最大并发 chat 数 |
| `PUBLIC_UPSTREAM_ENABLED` | `true` | 默认启用固定免认证提供商；设为 `false` 可关闭全部公共链路 |
| `PUBLIC_UPSTREAM_PROVIDERS` | `opencode,pollinations,felo` | 固定 provider ID；不接受任意提供商 |
| `PUBLIC_UPSTREAM_BASE_URL` | `https://opencode.ai/zen/v1` | 仅允许覆盖 OpenCode HTTPS 地址；Pollinations/Felo 端点固定 |
| `PUBLIC_UPSTREAM_MODELS` | 聚合免认证模型白名单 | 使用 `provider/model` 规范 ID（OpenCode 兼容历史裸 ID） |
| `PUBLIC_UPSTREAM_IMAGE_MODELS` | `pollinations/flux,pollinations/turbo,pollinations/zimage` | `/v1/images/generations` 的 Pollinations 免认证图片模型白名单 |
| `PUBLIC_UPSTREAM_TIMEOUT` | `20s` | 首响应超时后尝试其他公共 provider 或回退 Freebuff |
| `USER_AGENT` | 见下 | 覆盖 chat 请求的 User-Agent |
| `DEBUG_UPSTREAM` | 关 | `1` 时打印上游请求详情（token 脱敏） |

> `SITE_ACCESS_TOKEN`（仅 Web 应用）是托管控制台的**前门**：设置后，
> `POST /api/gate/verify` 负责校验访客提交的 token（SHA-256 恒定时间
> 比较）。访客要么在锁屏界面输入 token，要么用 `?token=…` 打开站点；
> 验证通过后浏览器保存在 `localStorage`，每次访问重新校验。它不影响
> `/v1` 接口——该接口始终由 `API_KEYS` 保护。

`USER_AGENT` 默认值（与官方 SDK 一致，实测任意版本均通过网关）：

```
ai-sdk/openai-compatible/0.10.7/codebuff ai-sdk/provider-utils/3.0.25 runtime/browser
```

## 公共免认证上游

默认情况下，代理会聚合三个固定公共链路：OpenCode Zen、免 key 的 Pollinations，以及 Felo 逆向网页协议；然后才回退到 Freebuff 会话链路。所有模型 ID 一律使用 `provider/model` 前缀规范形式，不带前缀的裸 ID 不会被列出也不可路由（完整目录见 [09-模型目录](09-模型目录.md)）。命中多个公共 provider 时按 `PUBLIC_UPSTREAM_PROVIDERS` 顺序尝试与回退（公共优先，最后回退 Freebuff）。设置 `PUBLIC_UPSTREAM_ENABLED=false` 可关闭全部公共上游，也可缩小 `PUBLIC_UPSTREAM_PROVIDERS` / `PUBLIC_UPSTREAM_MODELS` / `PUBLIC_UPSTREAM_IMAGE_MODELS`。`PUBLIC_UPSTREAM_BASE_URL` 只允许覆盖 HTTPS 的 `opencode.ai`，不会改变 Pollinations/Felo 的固定地址。

公共上游只接收 provider 自己构造的 JSON body 与 headers，不会收到下游 `Authorization`、`x-api-key`、Cookie 或 Freebuff 账号 token。超时、401、408、425、429、5xx 等瞬态失败会尝试其他匹配的公共 provider，再回退 Freebuff；普通 4xx 直接返回。Pollinations 的匿名 chat 层对部分提示词形态会返回 401（匿名抽签路由，与内容相关），白名单只保留实测可匿名调用的模型并排除 premium/可选 key 模型；Felo 没有官方 API，其网页协议可能变化。图片生成（`/v1/images/generations`）只支持白名单中的 `pollinations/*` 图片模型，匿名结果带 Pollinations 水印（`nologo` 需要 token，不会发送）。公共上游会接收白名单模型对应的提示词和代码，部署前请确认各服务条款与隐私要求。

公共上游默认开启时，独立 CLI 可以在没有 `AUTH_TOKENS` 的情况下直接服务白名单公共模型；若要使用 Freebuff 专属模型或在公共上游失败后回退认证链路，仍应配置 `AUTH_TOKENS` 或保存的登录凭证。若关闭公共上游，则独立 CLI 必须配置 token；没有 token 时代理会返回明确的可重试错误，不会崩溃。

## 常用命令

| 命令 | 说明 |
| ---- | ---- |
| `freebuff2api` / `bun run src/index.ts` | 启动代理 |
| `freebuff2api login` | 设备码登录 |
| `freebuff2api login --resume` | 恢复被中断的登录 |
| `freebuff2api login --force` | 重新登录（换账号/刷新 token） |
| `freebuff2api --help` | 帮助 |
| `freebuff2api --port 23333` | 覆盖监听端口 |
| `freebuff2api --listen-addr 127.0.0.1:9000` | 覆盖监听地址 |
| `freebuff2api --http-proxy http://127.0.0.1:7890` | 覆盖上游代理 |
| `node tools/model-availability.mjs` | 探测 `/v1/models` 返回的每个模型（会消耗额度） |
| `bun run typecheck` | 类型检查 |
| `bun run build:cli` | 打包到 `dist/index.js`（node 目标） |
| `DEBUG_UPSTREAM=1 bun run src/index.ts` | 带上游调试日志启动 |

## 代理内部端点

| 方法 | 路径 | 说明 |
| ---- | ---- | ---- |
| GET | `/healthz` | 公开存活状态 |
| GET | `/v1/models` | 可用模型列表（OpenAI 格式；仅 `provider/model` 前缀 ID，无裸别名） |
| POST | `/v1/chat/completions` | chat（流式/非流式） |
| POST | `/v1/images/generations` | 图片生成（Pollinations 免认证；`model` 需为白名单图片模型） |

## 部署相关

- 默认开启公共上游时，独立 CLI 可不配置 `AUTH_TOKENS` 直接使用白名单公共模型；使用 Freebuff 专属模型、公共上游回退或设置 `PUBLIC_UPSTREAM_ENABLED=false` 时，仍需 `AUTH_TOKENS` 或保存的 `freebuff2api login` 凭证。托管 Next.js 应用的 `AUTH_TOKENS` 仍可选，因为每个访客可以网页登录并获得自己的 `sk-fb-*` key。
- 托管模式未设置 `API_KEYS` 时 `/v1` 会 fail closed；公开前必须配置高熵的显式 key。
- 打包产物：`bun run build:cli` → `dist/index.js`（`package.json` 的
  `bin.freebuff2api` 指向它）
- 生产环境（托管）：托管检测到 Next.js 应用后用 `bun run build`
  （即 `next build`）构建；CLI 产物用 `bun run build:cli` 单独打包。
  运行时不依赖外部服务
- 生产环境变量与沙箱 `.env` 分开管理，用 `freebuff-deploy env` 系列命令设置

## 安全提示

- token 等于账号的 API 使用权，请保密，不要提交到仓库
- 不要在 `.env` 中明文存 token 并提交；优先使用托管环境变量或登录凭证
- 免费档有速率限制（实测 deepseek-v4-flash 每日约 6 次基础额度，
  按太平洋时区重置），使用需节制
