# 06 端到端测试记录

> 本文记录整个开发与逆向过程中的关键测试与结论，供复现与排查参考。
> 测试均使用真实账号（登录凭证位于
> `~/.config/freebuff2api/credentials.json`）。

  `Another instance of freebuff has taken over this session`，

## 阶段 3：chat 端点的 403 之谜（关键）

最初所有 chat 请求都返回 `403 free_mode_cli_required`，即使
session/run 都成功。经过：

1. MITM 抓取官方 CLI 成功请求（见 `tools/mitm-ssl-proxy.mjs`）
2. 变体二分（见 `tools/discover-gate.mjs`）

确定网关检查的是 **system 消息中的精确短语**
`You are Buffy, the strategic coding assistant`。

详见 [04-请求格式破解](04-请求格式破解.md) 的完整测试表。

## 阶段 6：opencode 端到端验收（第三方 OpenAI 客户端）✅

> 验收标准：用真实的第三方 OpenAI 兼容客户端（**opencode**）通过代理的
> `/v1` 接口完成一个小项目，证明"任何 OpenAI 客户端都能驱动 Freebuff
> 免费模型"。产物见
> [`tests/agentic/cases/opencode-demo/`](../../tests/agentic/cases/opencode-demo/README.md)。

| 步骤 | 结果 |
| ---- | ---- |
| 安装 opencode v1.18.14（官方安装脚本，`~/.opencode/bin`） | ✅ `opencode --version` 正常 |
| opencode 配置自定义 provider `freebuff`：`@ai-sdk/openai-compatible`，`baseURL` 指向代理 `http://127.0.0.1:18080/v1` | ✅ `opencode models freebuff` 列出模型 |
| 在 `tests/agentic/cases/opencode-demo` 运行 `opencode run --model freebuff/deepseek/deepseek-v4-flash --auto` 生成 fib 小项目 | ✅ 生成 `fib.js` + `fib.test.js` |
| opencode 自主排错：首次 `node fib.test.js` 因父级 `type: module` 报 `require is not defined`，它重读 `package.json` 改为 ESM 重写 | ✅ 重跑通过 |
| `node fib.test.js` 验收 | ✅ `All fib tests passed`（f(0)、f(1)、f(10) 共 3 断言，退出码 0） |
| 代理日志 | ✅ 4 次上游 chat 全部 `status 200`（模型 deepseek/deepseek-v4-flash） |

**结论**：opencode 通过 freebuff2api 代理完成了完整的真实编码任务
（写代码 → 跑测试 → 发现错误 → 修复 → 全部通过），端到端链路验收通过。

复现方式：

```bash
# 1. 启动代理（tmux 保持后台）
tmux new-session -d -s fba 'cd <repo> && LISTEN_ADDR=:18080 bun run src/index.ts'

# 2. 配置 opencode（~/.config/opencode/config.json）：
#    provider.freebuff = { npm: "@ai-sdk/openai-compatible",
#      options: { baseURL: "http://127.0.0.1:18080/v1", apiKey: "local" },
#      models: { "deepseek/deepseek-v4-flash": {} } }

# 3. 运行
cd tests/agentic/cases/opencode-demo
opencode run --model freebuff/deepseek/deepseek-v4-flash --auto "<任务描述>"
```

## 阶段 7：复杂任务验收（opencode 内置工具链）✅

> 验收标准：用 opencode 完成一个多文件复杂任务，充分调用其内置工具
> （读文件 / 写文件 / 编辑 / 跑 bash / webfetch）。产物见
> [`tests/agentic/cases/opencode-md2html/`](../../tests/agentic/cases/opencode-md2html/README.md)。

任务：零依赖实现 Markdown→HTML 转换器（`md2html.js` + `cli.js` +
`test.js`，覆盖标题 / 段落 / 列表 / 行内代码 / 代码块 / 链接 / 加粗），
再用 `node cli.js sample.md` 实际转换，并用 webfetch 抓取
`https://example.com`。

| 步骤 | 结果 |
| ---- | ---- |
| 会话信息 | agent=build，模型 `freebuff/deepseek/deepseek-v4-flash`，共 13 条消息 / **12 次上游 chat 调用**（代理日志全部 status 200） |
| 工具使用（会话导出统计） | `read` ×2、`write` ×5、`edit` ×2、`bash` ×6、`webfetch` ×2 |
| `node test.js` | ✅ 10 个断言全部通过（含 HTML 转义 `a < b & c` → `a &lt; b &amp; c`） |
| `node cli.js sample.md` | ✅ 输出含 `<h1>` `<ul>` `<pre><code>` `<a href="https://opencode.ai">` |
| webfetch `https://example.com` | ✅ 返回页面标题 "Example Domain" |
| 零依赖 | ✅ 未新增任何第三方依赖 |

**结论**：复杂任务端到端通过——opencode 通过代理完成 12 轮模型调用，调用
5 种内置工具（read/write/edit/bash/webfetch），自主处理了 ESM 环境
（重读 `package.json`），产出可运行的完整项目。
