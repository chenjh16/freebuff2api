## 阶段 8：Luna / DeepSeek Flash 新 session 对比诊断

官方源码确认两个模型必须使用独立的 root Agent：

| 模型 | Agent |
| ---- | ----- |
| `openai/gpt-5.6-luna` | `base2-free-luna` |
| `deepseek/deepseek-v4-flash` | `base2-free-deepseek-flash` |

官方 CLI 的 session POST 是**无 body**，并在 `x-freebuff-model` 中固定模型；等待室 GET
带 `x-freebuff-instance-id` 和 `x-freebuff-compact-session: 1`。同一账号同时只能持有一个
活动 session，因此两个模型不能在同一个 session 内切换，测试必须先结束旧 session，或使用
不同账号分别执行。

本次已通过代理执行两次全新 session 的最小 Chat：

| 模型 | 新 session / Chat 结果 | 结论 |
| ---- | ---- | ---- |
| `openai/gpt-5.6-luna` | HTTP `503 server_error`，约 2 秒 | 当前账号/上游未提供可用响应，不能证明模型永久不可用 |
| `deepseek/deepseek-v4-flash` | 历史完整 E2E 曾 HTTP 200；本次模型探测结果受账号 session/额度状态影响 | 代理链路可用，但需独立 session 复测 |

定位到的代理缺陷是：上游 session 创建返回 `409 model_unavailable` 或 `409 model_locked` 时，
早期实现可能将非 active 状态当作缓存状态并循环刷新，最终客户端只看到超时或笼统 503。
当前修复包括：

1. Session POST/GET 形状与官方 CLI 对齐（空 POST body、compact poll）；
2. 终态 session 不再无限循环；
3. 模型入场错误保留 `409` 和 `error.code`，与等待室/无健康 token 的 `503` 区分；
4. 新增上游请求形状和终态错误回归测试。

### 9.2 会话锁定时切换模型 → 409（而非 503）

Luna 会话活跃时经代理请求 deepseek，实测返回：

```json
{"error":{"message":"free session unavailable for deepseek/deepseek-v4-flash: model_locked (session is locked to openai/gpt-5.6-luna)","type":"upstream_error","code":"model_locked"}}

```

上游响应为 `409 model_locked` 且携带 `currentModel` / `requestedModel`，代理如实上抛，
不再伪装成 503。

| ---- | ---- | ---- | ---- |
| session POST body | 空（`content-length: 0`） | 空 | ✅ |
| session POST 头 | `Authorization` + `x-freebuff-model` + `Bun/1.3.14` UA（无 acting-user-id） | 相同 + `x-freebuff-acting-user-id` | ✅（上游容忍多余头） |
| agent-runs START | `{action, agentId, ancestorRunIds: []}` | 完全相同 | ✅ |
| chat UA | `ai-sdk/openai-compatible/0.0.0-test/...` | `.../0.10.7/...` | ✅（网关忽略版本） |

### 9.5 503 根因总结

1. **修复前缺陷**：session POST 返回 `409 model_unavailable` / `409
   model_locked` 时被当作缓存状态循环刷新，客户端最终只见超时或笼统 503。
2. **既有修复**：终态准入错误以有限 `409` + `error.code` 上抛；session POST/GET 形状对齐
   官方 CLI；session 池按模型固定。
3. **本轮新增**：`model_locked` 错误携带锁定模型名（上游 `currentModel`）；其余 session
   准入失败（`429` / `500` / `503` / `401`）保留真实状态码、`Retry-After` 与消息，不再
   屏蔽为 "no healthy upstream token available"（与官方 CLI 对 429/503 退避重试的语义一致）。
4. **实测**：双模型 200；切换模型 → `409 model_locked`。

新增调试工具：`tools/probe-session.mjs`（逐模型 session 准入探针，`--admit-only` 不耗
chat 额度）与 `tools/cli-probe.mjs`（PTY 驱动官方 CLI 探针，可选 MITM 抓包）。回归测试
见 `tests/unit/{upstream,session,server}.test.ts`。
