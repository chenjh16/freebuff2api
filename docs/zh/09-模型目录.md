# 09 — 模型目录与路由

> 统一模型目录：`provider/model` 前缀规范 ID、按供应商优先级的回退路由，
> 以及图片生成。实现见 `src/models.ts`、`src/public-upstream.ts`、
> `src/handler.ts`。

## 供应商前缀 ID

每个模型只有一种拼写：带供应商前缀的 `provider/model` ID。**没有不带前缀的裸
别名** —— 裸 ID 不会被 `GET /v1/models` 列出，也不可路由，因此模型 ID 总是
标明其供应商。

| 供应商 | ID 形式 | 示例 |
| ---- | ---- | ---- |
| Freebuff（需认证） | `freebuff/<注册表模型>` | `freebuff/deepseek/deepseek-v4-flash` |
| OpenCode Zen | `opencode/<model>` | `opencode/big-pickle` |
| Pollinations chat | `pollinations/<model>` | `pollinations/openai` |
| Pollinations 图片 | `pollinations/<model>` | `pollinations/flux` |
| Felo | `felo/<model>` | `felo/felo-chat` |

`GET /v1/models` 列出全部前缀 ID（去重、排序，OpenAI `list` 形状）。
`owned_by` 字段标明所属供应商：Freebuff 注册表模型为 `freebuff2api`，公共渠道
分别为 `opencode` / `pollinations` / `felo`。带前缀的 ID 总是路由到对应供应商；
当请求瞬态失败时，会按 `PUBLIC_UPSTREAM_PROVIDERS` 顺序（默认 `opencode,
pollinations, felo`）回退到其余匹配的公共 provider，最后才走认证 Freebuff
链路。

## Chat 模型（`POST /v1/chat/completions`）

### Freebuff（需认证）

Freebuff 注册表全部模型（如 `deepseek/deepseek-v4-flash`）以
`freebuff/<model>` 列出（如 `freebuff/deepseek/deepseek-v4-flash`）。它们需要
Freebuff token（`AUTH_TOKENS` 或已保存的登录凭证），并且是兜底链路。

### OpenCode Zen（免认证）— 4 个

`opencode/big-pickle`、`opencode/deepseek-v4-flash-free`、
`opencode/mimo-v2.5-free`、`opencode/nemotron-3-ultra-free`

实测 `hy3-free`、`north-mini-code-free` 匿名调用返回 401，已从白名单移除。

### Pollinations（免认证）— 8 个

`pollinations/openai`、`pollinations/openai-fast`、`pollinations/openai-large`、
`pollinations/qwen-coder`、`pollinations/mistral`、`pollinations/deepseek`、
`pollinations/grok`、`pollinations/perplexity-fast`

`gemini-flash-lite-3.1`、`perplexity-reasoning` 匿名调用返回 401，已移除。另外
Pollinations 匿名 chat 层对部分提示词形态也会返回 401（供应商侧的抽签路由，不
是代理的问题）；E2E 探针使用良性提示词并对瞬态失败重试。

### Felo（免认证，逆向网页协议）— 5 个

`felo/felo-chat`、`felo/felo-search`、`felo/felo-scholar`、`felo/felo-social`、
`felo/felo-document`

Felo 没有官方 API，其网页协议可能随时变化。

## 图片模型（`POST /v1/images/generations`）

Pollinations 免认证图片端点（`https://image.pollinations.ai`）：
`pollinations/flux`、`pollinations/turbo`、`pollinations/zimage`。

请求（OpenAI images API 形状）：

```json
{
  "model": "pollinations/flux",
  "prompt": "a tiny red circle on a white background",
  "size": "256x256",
  "n": 1,
  "seed": 42,
  "response_format": "b64_json"
}
```

| 参数 | 含义 |
| ---- | ---- |
| `model` | 白名单内任意 `pollinations/*` 图片模型（带前缀） |
| `prompt` | 必填文本提示 |
| `size` | `"WxH"` 像素尺寸，转为 `width`/`height` 转发 |
| `n` | 图片数量；每张使用 seed + i |
| `seed` | 可选；缺省为随机 |
| `response_format` | `b64_json` → 每项只有 `b64_json`；否则为 `url`（`data:` URI）加 `b64_json` |

响应：

```json
{ "created": 1786000000, "data": [{ "url": "data:image/jpeg;base64,...", "b64_json": "..." }] }
```

说明：上游调用为 `GET image.pollinations.ai/prompt/<prompt>?width=…&height=…&seed=…&model=…&format=jpeg`，无任何凭证。`nologo`（去水印）需要账号 token，**从不**发送 —— 匿名结果带 Pollinations 水印。图片在响应前同步抓取并 base64 编码，因此延迟随生成时间增长。图片生成使用独立的 ≥60s 单图超时，不受 `PUBLIC_UPSTREAM_TIMEOUT`（默认 20s）影响，因为匿名图片渲染比 chat 慢。

## 流式兼容（严格客户端）

所有公共 chat 流在转发前统一规范化，使严格解析器（Cherry Studio 所用的 Vercel
AI SDK，遇到未知或缺失的 finish chunk 会以 `AI_FinishReasonError` 中止）始终
收到格式良好的流：

- 保证终结 chunk `finish_reason: "stop"` —— 上游未发 finish chunk 就结束
  （OpenCode 免费层偶尔在 `reasoning_content` 后截断）或发出 `"other"` 等非
  标准 reason 时，代理会重写/补发 `"stop"`。
- `content` / `reasoning_content` 增量与 usage chunk 原样保留；畸形行与垃圾
  尾随 chunk（如 OpenCode 的 `{"choices":[],"cost":"0"}`）被丢弃；流总是以唯一
  的 `data: [DONE]` 结束。

已知上游行为：`opencode/deepseek-v4-flash-free` 是免费层，**随机性**地出现只输出
推理、最终回答为空的结束（模型想了但没回答）。代理无法凭空生成内容；有了该修复
客户端至少收到干净的 `stop` 终结而不是报错。遇到空回复请重试（或换用其他模型）。

> 各渠道细节、供应商怪癖与 Cherry Studio `AI_FinishReasonError` 案例见
> [10-公共上游渠道](10-公共上游渠道.md)。

## 路由与回退

- **公共 chat：** 公共路由开启且请求的前缀模型匹配公共 provider 时，优先走公共
  路径。瞬态失败（`401/408/425/429/5xx` 或超时）回退到其余匹配的公共 provider，
  最后才走认证 Freebuff 链路（如有 token）；不可重试的 4xx 直接返回。
- **公共图片：** 仅 Pollinations；瞬态 provider 失败直接上抛（由客户端重试），
  不换 provider 重放。
- **Freebuff 模型：** `freebuff/<model>` 在发起 session/run/chat 前会被规范化为
  注册表模型 ID（去掉 `freebuff/` 命名空间），因此上游始终看到正确的模型。

## 配置项

| 环境变量 | 默认值 | 作用 |
| ---- | ---- | ---- |
| `PUBLIC_UPSTREAM_ENABLED` | `true` | 关闭全部公共 provider |
| `PUBLIC_UPSTREAM_PROVIDERS` | `opencode,pollinations,felo` | 启用的 provider 与回退顺序 |
| `PUBLIC_UPSTREAM_MODELS` | 聚合白名单 | 公共 chat 模型白名单（`provider/model` ID） |
| `PUBLIC_UPSTREAM_IMAGE_MODELS` | `pollinations/flux,pollinations/turbo,pollinations/zimage` | 图片模型白名单 |
| `PUBLIC_UPSTREAM_TIMEOUT` | `20s` | 回退前的首响应超时 |

完整配置参考：[07-配置与使用](07-配置与使用.md)。
