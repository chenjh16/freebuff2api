# 08 — 托管部署（Freebuff）

## 为什么是 Next.js？

核心代理是一个独立的 Bun/Node 服务器（`src/index.ts`）。Freebuff 托管只
构建 **React 系项目**（Vite + React、Next.js、Create React App），因此为了
免 VPS 部署，仓库额外内置了一个 Next.js App Router 应用（`app/`），把
**完全相同的**请求处理器（`src/handler.ts`）挂到标准 OpenAI 接口后面。

```
┌─────────────────────────── 托管应用（Next.js） ────────────────────────────┐
│  GET  /healthz               →  ┐                                          │
│  GET  /v1/models             →  │  app/lib/proxy.ts（惰性单例）            │
│  POST /v1/chat/completions   →  ┘  ├─ loadConfig()                        │
│                                    ├─ ModelRegistry（免费 Agent 映射）     │
│                                    ├─ TokenManager（免费会话）             │
│                                    ├─ RunManager（Agent 运行）             │
│                                    └─ createHandler()（来自 src/handler.ts）│
└────────────────────────────────────────────────────────────────────────────┘
```

同一份代码路径意味着本地 CLI 服务器与托管端点行为完全一致（会话准入、
503 等待室、模型锁定、流式、CLI 网关 system 标记注入）。

## 公开接口

- **域名：** `https://freebuff2api.freebuff.app`
- **Base URL：** `https://freebuff2api.freebuff.app/v1`

| 方法 | 路径 | 说明 |
| ---- | ---- | ---- |
| GET | `/` | 落地页 / 在线控制台（状态、模型列表、试聊） |
| GET | `/healthz` | 存活 + 模型注册表 + 令牌/会话状态 |
| GET | `/v1/models` | 当前可用的免费模型 |
| POST | `/v1/chat/completions` | Chat —— JSON 或 SSE 流式 |

API 鉴权方式为 `Authorization: Bearer <key>` 或 `x-api-key: <key>`。

## 部署环境变量

| 变量 | 必需 | 默认值 | 说明 |
| ---- | ---- | ------ | ---- |
| `AUTH_TOKENS` | ✅ | — | Freebuff auth token（逗号分隔）。未设置前代理返回 503 并给出明确提示。 |
| `API_KEYS` | 否 | `sk-freebuff2api-2026` | 客户端必须携带的 key。托管应用未配置时回退到该默认值，保证公开端点不会裸奔；设置环境变量即可覆盖。 |
| `UPSTREAM_BASE_URL` | 否 | `https://www.codebuff.com` | Freebuff 后端地址。 |
| `REQUEST_TIMEOUT` | 否 | `15m` | 上游请求超时。 |
| `ROTATION_INTERVAL` | 否 | `6h` | Agent run 轮换间隔。 |
| `MAX_BODY_SIZE` | 否 | `16MB` | Chat 请求体上限。 |
| `MAX_CONCURRENT_REQUESTS` | 否 | `32` | 最大并发 chat 请求数。 |

与
[07-配置与使用](07-配置与使用.md) 中的变量一致；托管应用从部署环境读取。

## 部署步骤

1. 推送仓库（Freebuff 托管从关联仓库构建）。
2. 打开 **Deployments** 面板执行首次 **Deploy**——托管检测到 Next.js
   应用，自动执行 `next build` 并托管到项目域名（首次之后可用
   `freebuff-deploy start` 重新部署）。
3. 在部署环境中设置 `AUTH_TOKENS`（Deployments → env）。未设置时站点与
   `/healthz` 保持在线，但 `/v1/*` 会返回 `503`「proxy is not configured」。
4. 验证：

```bash
# 健康检查（公开）
curl https://freebuff2api.freebuff.app/healthz

# 模型列表（需鉴权）
curl https://freebuff2api.freebuff.app/v1/models \
  -H "Authorization: Bearer sk-freebuff2api-2026"

# 聊天（流式）
curl https://freebuff2api.freebuff.app/v1/chat/completions \
  -H "Authorization: Bearer sk-freebuff2api-2026" \
  -H "Content-Type: application/json" \
  -d '{"model":"deepseek/deepseek-v4-flash","stream":true,"messages":[{"role":"user","content":"Hello!"}]}'
```

## 行为说明

- **健康检查：** `AUTH_TOKENS` 未设置前 `/healthz` 返回
  `200 {ok:false, configured:false}`，让托管健康检查保持绿色；其它端点
  返回带明确原因的 503。
- **CORS：** `/v1/*` 开放（预检返回 `204`），浏览器客户端可直接调用。
- **流式：** SSE 透传；chat 路由允许长连接（max duration 300 s）。
- **账号限制不变：** 每个账号同一时间只有一个免费会话（约 1 小时），且
  锁定单一模型；会话被占用时请求其它模型返回 `409 model_locked` 并附上
  锁定模型名（代理不会把它掩盖成 503）。
- **状态：** 会话池 / run 管理器 / 模型注册表常驻服务器进程；冷启动
  （重新部署）时惰性重建。
- **扩展：** 单账号 = 单并发会话，因此托管端点同一时刻服务一个模型；
  在部署环境配置多个 `AUTH_TOKENS` 可让代理在多个账号间轮换。

## 托管应用本地开发

```bash
bun run dev        # next dev —— 同一套 /v1 接口 + 落地控制台
bun run build:web  # next build —— 托管构建的产物
```

CLI 服务器不受影响：`bun run dev:cli`（或 `bun run start`）。
