# 02 登录流程（device-code）

> 本文记录 `freebuff2api login` 是如何逆向官方 Freebuff CLI
> （[CodebuffAI/freebuff](https://github.com/CodebuffAI/freebuff)）的登录流程的。
> 实现见 `src/login.ts`。

## 背景

需要登录链接与凭证的原因：免费模式需要账号的 auth token（与浏览器会话
一致）。手动复制 token 既麻烦又容易泄露，因此复刻了官方 CLI 的
"设备码式"（device-code）登录：打印一个一次性链接，用户在浏览器完成
登录，CLI 轮询拿到凭证。

## 官方 CLI 的登录流程

### 1. 请求一次性登录码

```
POST {base}/api/auth/cli/code
Content-Type: application/json

{ "fingerprintId": "<安装指纹>" }
```

响应（HTTP 200）：

```json
{
  "loginUrl": "https://freebuff.com/login?auth_code=…",
  "fingerprintHash": "<64位hex>",
  "expiresAt": 1786030…
}
```

### 2. 用户打开 `loginUrl` 完成浏览器登录

无需手动复制 token，安全。

### 3. 轮询登录状态直到成功

```
GET {base}/api/auth/cli/status?fingerprintId=…&fingerprintHash=…&expiresAt=…
```

- 尚未登录时返回 `401 "Authentication failed"`，需要**静默重试**
  （与官方客户端一致）
- 登录完成后返回：

```json
{
  "user": {
    "id": "280d0ec6-…",
    "name": "Never More",
    "email": "nevermore.thu@example.com",
    "authToken": "<token>",
    "fingerprintId": "…",
    "fingerprintHash": "…",
    "credits": …
  }
}
```

### 4. 保存凭证

保存到 `~/.config/freebuff2api/credentials.json`（与官方 CLI 同构，
`default` 键下）：

```json
{
  "default": {
    "id": "…",
    "name": "…",
    "email": "…",
    "authToken": "…",
    "fingerprintId": "…",
    "fingerprintHash": "…"
  }
}
```

## 安装指纹（fingerprint）

- 官方 CLI 用硬件派生的持久指纹标识"设备"
- freebuff2api 持久化一个随机 ID 到
  `~/.config/freebuff2api/fingerprint`，格式 `codebuff-cli-<随机>`
- 作用：稳定跨进程的设备身份，也是后续登录/会话的关联依据

## 实现细节（src/login.ts）

| 函数 | 职责 |
| ---- | ---- |
| `requestLoginCode()` | 第 1 步：POST 登录码，校验响应结构 |
| `pollLoginStatus()` | 第 3 步：带超时（默认 5 分钟）轮询，容忍 401 |
| `runLoginCommand()` | 编排：恢复/新建/强制登录，落盘凭证 |
| `getFingerprintId()` | 读取或生成持久指纹 |

### 命令

```bash
bun run login                     # 开始登录并等待浏览器确认
bun run login -- --resume         # 恢复被中断的登录（同一链接）
bun run login -- --force          # 忽略已存凭证，重新登录
```

中断的登录保存在 `~/.config/freebuff2api/pending-login.json`，
支持 `--resume` 继续等待。

## 注意事项（实测经验）

- **同一账号同一时间只允许一个活动会话**。若在其他地方（如官方 CLI）
  创建了会话，会报 `Another instance of freebuff has taken over this session`
  ——需要重新登录（换账号或用 `--force`）。
- 凭证即令牌：`AUTH_TOKENS` 未设置时，服务器自动使用登录保存的 token。
- 登录地址可通过 `LOGIN_BASE_URL` 覆盖（默认 `https://freebuff.com`）。

## 验证结论

- ✅ 完整走通：生成链接 → 用户浏览器登录 → 轮询拿到 user 记录 → 落盘
- ✅ 恢复流程：中断后 `--resume` 可用同一链接继续等待
- ✅ 服务器端自动使用保存的 token（`/healthz` 的 `acting_user_id` 正确）
